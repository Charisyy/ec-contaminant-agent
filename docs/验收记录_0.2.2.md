# 0.2.2 问答修复与验证

日期：2026-10-19。

## 问题与修复

1. 原问答入口要求每次回答先执行科研工作流，独立问候没有合适的实体与分析任务。增加精确的本地问候与使用帮助入口；此类回复不创建 Agent、不请求模型，并在页面明确标注。含有分析任务的问候句仍进入研究流程。
2. DeepSeek 默认启用思考模式，其多步工具调用要求续传 `reasoning_content`。当前通用适配器未保留该字段；预设与连接测试显式使用官方支持的非思考模式。参照：https://api-docs.deepseek.com/guides/thinking_mode/ 。这是已核实的兼容性问题；现有截图未保留具体后台错误，不能把截图中所有失败都归因于这一项。
3. 原界面把模型请求、返回格式和证据校验失败合并显示。现在区分失败阶段，返回具体校验原因、服务状态码与错误编号；日志不记录凭据、问题正文或原始模型响应。

## 验证方式

本轮自动化回归结果：**58 通过、0 失败、0 跳过**，运行约 64 秒。另行完成 Microsoft Edge 页面检查，包含独立问候与模拟接口科研问答；未调用真实付费服务。

- 独立问候在禁止创建 Agent 的条件下仍可正常回应；混有实体分析的句子不会被当作问候吞掉。
- 模拟服务严格检查 DeepSeek 请求中的非思考参数，并拒绝不支持的 `json_schema` 响应格式；完整执行工具调用与结果返回。
- 分别模拟接口参数错误、认证、余额、频率限制、模型不存在及服务异常，检查阶段与状态分类；包装异常也能识别，原错误文本不会返回。
- 保留真实科研问题必须执行工具、不得引用未查询实体或来源、不得输出综合风险分数的检查。
- 浏览器验证问候回复不增加模型请求次数，科研问答仍执行实际工具。无真实 Key、无付费 API 调用。

数据库、已保存的本地模型设置和依赖环境保持不变。真实服务调用效果需配置后验证；基础测试成功不代表科研回答或毒性预测已获验证。
